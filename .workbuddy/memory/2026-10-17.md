## 关键教训（都是实测踩出来的）

1. **照护不能只看 presence**。第一版按 `presence=1` 判活动，把 23:55–06:55 连续 425 分钟记成
   "夜间活动" —— 人躺床上 presence 也是 1。生成器 `activity_level` 三档是
   睡觉 0~12 / 醒着静止 25~55 / 走动 60~100，**阈值 20 正好落在空隙**，用它分
   在床静息 / 醒着活动才对。

2. **`insufficient_data` 是状态标记不是历史观察**。覆盖率恢复后旧标记还留在时间轴上，
   会出现"同期有正常记录、却另有一行数据不足"。每次推导先 `DELETE` 旧标记再按需写一条。

3. **Vue 里 `v-if="arr"` 空数组是 truthy** —— 警告条永远显示。必须写 `v-if="arr.length"`。

4. **补历史必须在后端启动之初跑**。我先起了常驻生成器（把时间线推到"现在"）再补 24h，
   采集端把整批判为「时间倒退」，而能耗积分对倒退**按设计不计**（`gap<=0 → None`），
   于是能耗页显示 0.00 kWh。修法：`scripts/repair_energy.py` 用已存 `power_w` 与观测间隔
   重算派生列（116,583 行），不改原始读数。

5. **常驻生成器追上真实时间后会降到 1 倍速**（`--max-ahead` 限速），自动场景间隔
   2.5~5.5 小时 → 现场演示等不起。所以必须有 `trigger_scenario.py` 手动入口。

6. 幂等靠"时间窗 + 业务键"，因为 `alarms`/`suggestions` 没有 event_id/dedupe 列，
   而 `app_rw` 没有 DDL 权限（既定约束）。告警用 `(alarm_code, device_id, created_at±1s)`；
   建议用 `reason_json.dedupe`。

| 验收 | `backend/tests/floorplan_check.py` → **39 PASS / 0 FAIL** |

## 关键决定（别推翻）

1. **几何存文件不存库**：`rooms` 表无几何字段，加字段要 DDL，而 `app_rw` 无 DDL 权限。
2. **房间码必须过 `rooms` 表校验**（进 MQTT topic）；`is_circulation=true` 的交通空间是唯一例外，
   且**真实房间不许标成交通空间**、交通空间不许用真实房间码。
3. **底图用 Pillow 真解码**（不信 content-type/扩展名），统一转 PNG、清 EXIF、过大自动缩到长边 2000；
   **刻意不收 SVG**（可带脚本）。
4. **上传底图 = 清空旧框选**（坐标系变了，保留旧框全是错的）。
5. **有底图时画布尺寸必须等于图片尺寸**，否则 400。
6. **有底图时不画墙线**（墙在图里），房间名+读数移到**左上角 + 白色描边**
   —— 否则和图片自带的房间名叠成一团糊字（这个是截图才发现的）。

## 踩坑

- `Write` 工具写 `/tmp/xxx.js` 落到了奇怪位置（`\tmp\ed1.js`），后来改用 bash heredoc + `$(cat ...)` 传参。
- 自动化画框：`setPointerCapture` 对合成 pointerId 会抛错 → 组件里必须 try/catch 包住，
  否则自动化测试一按下去就崩。（真实鼠标不受影响）
- `preserveAspectRatio="xMidYMid meet"` 有留白，屏幕坐标 ↔ 用户坐标必须按
  `min(rect.w/vb.w, rect.h/vb.h)` 算缩放并加居中偏移，否则画出来的框偏移。

## 测试痕迹已清理

测试用的示意图底图与 4 个框选**已恢复默认**（`source=default`、8 个区域、无底图）。
要试就点「编辑户型」上传自己的户型图。

# 2026-10-17（续 2）· 框可拖动缩放 + 房间名自定义 + 多套房切换

## 三个需求与落点

| 需求 | 实现 |
|---|---|
| 选中框改大小/位置 | `FloorplanEditor.vue` 加 `drag` 状态：矩形上拖=移动，8 个手柄=缩放；限制最小 12 单位、不出画布 |
| 房间名用户自定义 | 名字**唯一真相是 `rooms.name`**：保存时差异写回 + `catalog.refresh()`；交通空间名只存 `config/floorplans/{home}.json` |
| 多套房切换 | `GET /api/homes` + `stores/home.js`（localStorage 记住）+ 顶栏下拉；`home_id` 贯穿房间/设备/户型/能耗/告警/照护/建议 |

新增：`scripts/seed_second_home.py`（建「工作室单间」2 房 6 设备，幂等，`--reset` 重建）。

## 关键决定（别推翻）

1. **户型路径按套房隔离**：`config/floorplans/{home_id}.json` + `config/floorplans/{home_id}/base.png`。
2. **只有 1 号房有内置默认户型**；别的套房没画过 → `source="empty"`、空画布 + 提示。
   套用内置户型 = 画出"别人家"，比空着更误导。
3. **`/api/devices` 与 `/api/energy` 的 `home_id` 缺省是 1（不是 None）**：
   旧大屏不传该参数，缺省 None 会突然多出别人家的设备/电费。M6 三组端点缺省 None（只新前端调用）。
4. **房间改名会刷新设备目录**，否则设备页还显示旧名（同"加了设备却看不见"那个坑）。
5. **生成器按 `device.home_id` 发布**（原来统一用 `devices[0].home_id`，多套房会把 B 家数据发到 A 家 topic）。
   订阅改成 `smart_home/+/...` 通配，`_on_message` 判场景用 `endswith('/system/scenario')`（通配后收到的 topic 是具体的）。

## 踩坑

- 自动化测拖拽：`pointerdown` 必须派发到**手柄/矩形元素**上（处理函数带 `.stop`），
  派发到 `<svg>` 会走"画新框"分支，表现为"拖了没反应、还多出一个框"。
- `agent-browser` 每次 `open` 是新上下文，`localStorage` 不保留 → 测多套房要先在页内切一次。
- `FloorPlan.vue` 的"空户型不回落默认"必须同时覆盖 `source==='empty'`，否则二号房会显示一号房的 7 间房。
- `/api/health` 的设备数是**全库**（38 台）；页面底部统计改为按当前套房的 devices 自己数，不能再用 `system.deviceStats`。

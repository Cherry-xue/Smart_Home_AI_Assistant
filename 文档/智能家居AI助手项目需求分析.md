# 《基于云边端协同与多智能体协作的智能家居 AI 助手平台》项目

# 一、这个项目是做什么的

**通俗一句话定义**：

​		这是一个**家庭 AI 管家系统**，不是换个花样让你多下一个 App 喊一句"开灯"，而是通过**多模态感知（语音/图像/传感器）**真正理解"家里发生了什么、说话的是谁、他想要什么"，再由**多个 AI 智能体分工协作**，把"关灯"升级为"完成任务"——守住家的安全、管好电费账单、照护老人小孩、搞定全屋设备的联动编排，打造一个懂你、省心、可托付的家庭智能服务中枢。

**区别于普通智能音箱 / 传统自动化的核心亮点**

1. 普通智能家居：一声令下一个动作，**固定规则、听不懂上下文、换个说法就失效**；

2. **多模态 \+ 记忆驱动的认知能力**：能听懂自然语言与方言、识别说话的家庭成员、记住各人的偏好与禁忌、结合时间/天气/设备状态理解真实意图，**从"控制"走向"理解"**；

3. **多智能体协作**：拆分不同 AI 角色，各司其职，模拟一个家庭服务团队——**一个管安防应急、一个管能耗账单、一个管健康照护、一个管家务编排、一个管家事助理**，比单一规则引擎更能处理"省电"与"舒适"、"个性"与"多用户"之间的冲突。

# 二、项目背景与痛点

## 2\.1 行业现状痛点

- **设备品牌多、协议碎、App 更碎**：一个家庭平均要装七八个厂商 App，配网、联动、排查全靠用户自己摸索，学习成本极高；

- **自动化多是"死规则"**：IFTTT 式定时规则只能处理简单条件，无法理解上下文和长期偏好，换个场景就失效，更不会多步失败重试；

- **主动智能几乎为零**：设备只会等你下令，不会预判"快下雨了窗户还开着""爸妈今晚没起夜活动"，价值停留在遥控器层面；

- **家庭是多用户系统**：同一句"我冷"，老人、儿童、年轻人代表的温度诉求完全不同，现有系统缺少成员识别与偏好协商机制；

- **高风险操作容错率极低**：门锁、燃气、烟感的误触发或漏触发，后果不可承受，而现有联动的可靠性完全依赖云端网络；

- **隐私顾虑强**：摄像头、麦克风常年在线被广泛质疑"不可信"，一旦断网或厂商停服，基础自动化就集体失效。

## 2\.2 项目解决的核心问题

用 **多模态感知 \+ 长期记忆 \+ 多智能体协作 \+ 云边端协同** 解决：**智能家居"控制门槛高、听不懂人、不懂家庭成员差异、不会主动服务、云端一断就瘫痪"**的行业痛点。

# 三、系统整体架构

整体四层架构：**感知与数据层 → 家庭认知引擎层 → 多智能体业务层 → 前端展示层**

## 1、 感知与数据层（家庭数据底座）

汇聚全屋多模态数据与知识：

- 设备状态数据：灯光、空调、窗帘、门锁、摄像头、燃气/水浸/烟感传感器；

- 环境与能耗数据：温湿度、光照、空气质量、实时功率、分时电价、光伏/储能；

- 家庭档案数据：成员画像、作息习惯、偏好禁忌、权限配置、家庭日历；

- 外部服务数据：天气、空气质量、日历日程、社区物业通知。

处理动作：统一设备抽象（设备能力建模，屏蔽品牌差异）、数据清洗、本地优先存储。

## 2、 核心智能层：家庭认知引擎

整个系统的大脑，负责所有智能推理：

- 多模态输入融合（语音、图像、传感器、上下文）

- 说话人识别与家庭成员画像匹配（判断"谁在说话、按谁的习惯来"）

- 意图理解与复杂任务规划（把"我要睡了"拆解成关灯、降帘、布防、调温等多步动作）

- 长期记忆与偏好学习（记忆形成、更新与遗忘策略）

- 云边端调度决策（哪些本地执行、哪些上云推理）

## 3、 业务层：五大智能家居智能体

真实家庭事务分工，拆分**5 个独立智能体**，互不干扰、协同工作，适合团队分工开发：

### 智能体1：场景编排与设备控制智能体

​		负责自然语言创建/修改家庭自动化场景（"每天晚上十点半关灯关窗帘"），自动把抽象描述映射为设备能力清单，执行冲突检测与失败重试降级，并且实现跨品牌跨协议统一控制。

### 智能体2：安防与应急处置智能体

​		负责入侵识别、燃气泄漏、水浸、烟感、门窗未关等家庭安全场景，自动分级告警、触发联动处置（关阀、锁门、录像、推人/推物业），对高风险动作执行二次确认，全程留痕可审计。

### 智能体3：能源优化智能体

​		负责家庭能耗分析：结合分时电价、光伏发电、储能余量、充电需求做用能调度，给出省钱省碳的调度策略与能耗报告（何时开空调、何时给车充电、哪些待机功耗该砍掉）。

### 智能体4：健康照护智能体

​		负责老人跌倒检测、长时间无活动预警、用药提醒、儿童看护与作息管理；以非摄像头手段优先（毫米波雷达、门磁、水电使用节律），在识别异常时按家庭预案通知子女或社区。

### 智能体5：家务助理与主动服务智能体

​		负责家庭事务的日常助理工作：耗材与食材库存识别、补货建议、快递与日程提醒、家庭成员事项协同；并在合适时机主动提出服务建议，但严格遵守打扰控制策略，可解释、可关闭。

## 4、 前端展示层

​		用户交互层：语音入口（本地唤醒/离线指令）、移动端 App、家庭中控屏、Web 管理后台（场景编排、权限管理、设备地图、审计日志、能耗看板）。

- **agent1-编排控制.html** — 左侧自然语言输入框，右侧实时生成设备能力清单与执行步骤。会展示意图理解 → 能力映射 → 冲突检测的全过程。内置 3 个场景：睡眠模式、观影模式、起床模式。**这个页面最适合演示**：输入"把家里调成看电影的样子"，右侧会列出 6 个设备的 11 个动作，并把相冲突的"主灯全亮"自动剔除。
- **agent2-安防应急.html** — 家庭平面示意图，传感器节点实时呈色。触发演示：点"燃气报警"，图上对应位置标红，下方处置时间轴依次滚动（关阀→开窗→推送→联系紧急联系人），高风险动作弹出二次确认框。内置燃气、水浸、非法闯入 3 个事件。
- **agent3-能耗优化.html** — 分时电价曲线 + 24 小时用能曲线叠加 + 本月账单对比 + 调度建议卡片（省 ¥XX/月）。点击任一建议会显示"为什么这么建议"的可解释说明。内置夏季高温月与春秋过渡月两套数据。
- **agent4-健康照护.html** — 老人/看护对象的时间轴活动轨迹、异常事件告警卡、用药打卡记录。内置"连续 6 小时无活动"触发一次预警的完整演示链路。
- **agent5-家务助理.html** — 待办流形式，每条主动建议都标出**推荐原因**（关联了哪条记忆或哪个传感器数据）与**打扰等级**。右上"免打扰"开关打开后，非紧急建议自动隐藏，演示"主动但不烦人"。

# 四、核心业务流程

**完整闭环流程**：

1. 输入侧：用户语音/文字/手势，或传感器自动触发事件；

2. 认知理解：多模态融合 \+ 说话人识别 \+ 家庭成员画像匹配，理解真实意图；

3. 智能路由：任务被判定属于哪一个（或哪几个）家居智能体的业务范围；

4. 任务规划：由认知引擎拆解为可执行的多步设备动作序列，进行冲突检测与优先级裁决；

5. 执行与降级：下发控制指令，失败自动重试，网络不可用时切本地规则降级执行；

6. 反馈与学习：结果可视化回传用户，主动操作需确认，用户反馈写入长期记忆。

# 五、项目创新点

1\. **认知创新：从"指令执行"升级为"意图 \+ 记忆理解"**

解决传统智能家居"只会机械执行、不懂上下文、不懂家庭成员差异"的问题，实现多模态融合理解、说话人识别、长期偏好记忆。

2\. **架构创新：云边端协同 \+ 多智能体分工协作**

摒弃单一规则引擎与云端黑箱，采用本地实时处理保障隐私与可用性、云端大模型负责复杂推理，业务侧由专业化智能体分工，用于处理安防、舒适、能耗等互相冲突的目标。

3\. **业务创新：全场景家庭服务闭环**

覆盖设备控制、安防应急、能耗管理、健康照护、家务助理五大核心场景，兼顾高风险的门锁燃气与情感价值的老人照护，落地性强。

4\. **效果创新：主动服务，但可控、可解释、可关闭**

每条主动建议都能说明"依据什么推荐"，提供打扰分级、免打扰时段与一键关闭，解决智能音箱"越智能越烦人"的体验陷阱。

# 六、技术栈

- **边缘/中台**：Home Assistant / 开源接入框架 + MQTT Broker，**轻量易部署、树莓派可跑**

- **设备协议**：Matter / Thread / Zigbee2MQTT / Wi-Fi / 蓝牙，**优先接入 Matter 生态**

- **大模型**：本地开源模型（Qwen、Llama 小参数量版本）负责意图理解与本地推理，复杂任务调用免费/低价云端 API 兜底（**任选**）

- **Agent 核心**：LangChain / LangGraph（实现任务规划与智能体编排）

- **向量数据库**：Chroma（家庭记忆与设备知识的轻量向量检索）

- **前端**：Vue3 / Element Plus（Web 管理端）**与**移动端 App（**任选其一即可演示**）

- **数据库**：SQLite（本地轻量）/ MySQL(**任选**) + 时序存储用于能耗数据

- **语音链路**：Whisper 类开源 ASR + 本地离线唤醒词 + Edge TTS 合成，**可纯本地运行**

- **版本管理工具：**git

# 七、常见疑问

## 1、 这个项目难度大吗？

**难度适中**：语音控制、场景联动这些基础功能用开源框架几天就能跑通；多模态理解、长期记忆、多智能体冲突裁决作为创新拔高点，**可繁可简**——按文档第八章的演示页保照也能讲清楚，接真设备可继续深入，保底能做完、上限很高。

## 2、 和普通智能家居/智能音箱项目有什么区别？

​		普通项目：只会喊一动一做的语音控制与定时规则；本项目：**会理解意图、会识别家庭成员、会记住偏好、会对冲突目标做多智能体协商、覆盖安防/能耗/照护等完整业务**，技术先进性与业务完整度远超普通联动项目。

## 3、 没有全套真设备怎么做？

​		一是 MQTT 模拟设备（写脚本模拟几十个虚拟开关和传感器），二是 Ha 官方 Demo 环境，三是按本需求的五个演示页做**真设备接入前的软件演示**，成本几乎为零；硬件并非前置条件。

# 八、项目最终成果

- 一套支持多模态理解与长期记忆的家庭认知引擎（含 Agentic 任务规划）

- 五个专业化家庭服务智能体协作系统

- 跨品牌、跨协议的统一设备抽象层与 Matter 接入适配

- Web 管理端 + 移动端的可视化控制平台（含五个智能体演示页）

- 完整项目文档、测试报告、创新说明
